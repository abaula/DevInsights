# Справочник разработчика: Управление памятью, типы и контракты данных в современном C#

Эта статья предназначена для быстрого поиска ответов (шпаргалка/справка) по поведению типов данных, оптимизации аллокаций и передаче параметров в C# (.NET 6+).

## 1. Базовое разделение: Стек vs Куча

| Категория | Типы данных | Где размещается | Как передается по умолчанию | Нагрузка на GC |
| :--- | :--- | :--- | :--- | :--- |
| **Ссылочные** (Reference) | `class`, `interface`, `delegate`, `string`, массивы (`T[]`) | Всегда в куче (Heap) | По значению ссылки (копируется только 4/8 байт адреса) | Да (управляется сборщиком мусора) |
| **Значимые** (Value) | `struct`, `enum`, встроенные примитивы (`int`, `double`...) | На стеке (локальные переменные) или в куче (поля классов, при боксинге) | Копированием всех байт данных (by value) | Нет (если на стеке) |

## 2. Матрица современных типов данных (.NET 6+)

### `ref struct` (Stack-Only)
Тип, для которого компилятор жестко гарантирует нахождение строго на стеке. Главный представитель — `Span<T>` / `ReadOnlySpan<T>`.
* **Плюсы**: Zero-Allocation (0% нагрузки на GC), безопасная работа с памятью (`stackalloc`, нативные указатели, срезы массивов) без ключевого слова `unsafe`.
* **Ограничения**:
  - Не может быть полем `class` или обычной `struct` (только внутри другого `ref struct`).
  - Нельзя упаковывать (Boxing к `object` или интерфейсам запрещен).
  - Нельзя использовать в асинхронных методах между операторами `await` (стейт-машина асинхронности размещается в куче).
  - Нельзя захватывать в лямбда-выражения (замыкания).
* **Современное дополнение (C# 11+)**: Ключевое слово **`scoped`**. Гарантирует компилятору, что ссылка (например, `Span<T>` или `ref` параметр) не «сбежит» за пределы текущей области видимости. Позволяет использовать `ref struct` в местах, где компилятор иначе бы выдал ошибку *CS8352* (например, при присваивании полей или в сложных лямбдах).

### `readonly struct`
Обычная структура, все поля которой имеют модификатор `readonly`.
* **Плюсы**: Защищает от создания компилятором скрытых **защитных копий** (defensive copies) при передаче параметров по ссылке только для чтения (`in`). Позволяет JIT-компилятору агрессивно оптимизировать код, зная, что данные не изменятся.

### `record` и `record struct`
Типы, созданные для семантики значений (Value Semantics) и быстрой декларации неизменяемых данных (DTO).
* **`record` (или `record class`)**: Ссылочный тип. Всегда в куче. Сравнивается по значению свойств, а не по адресу ссылки.
* **`record struct`**: Значимый тип. По умолчанию изменяем (mutable). Для иммутабельности используйте **`readonly record struct`**. Объединяет легкость структуры на стеке и удобство синтаксиса записей, включая поддержку выражения **`with`** для создания модифицированной копии с изменением отдельных свойств.

## 3. Шпаргалка по модификаторам параметров и возврата

Все эти модификаторы передают данные по ссылке (управляемый указатель под капотом), но имеют разные компиляторные контракты.

```text
                  ┌─────────────────────────────────────┐
                  │    Способ передачи параметров       │
                  └──────────────────┬──────────────────┘
                                     │
            ┌────────────────────────┴────────────────────────┐
   [ Входной параметр ]                               [ Выходной / Двунаправленный ]
            │                                                 │
    ┌───────┴───────┐                                 ┌───────┴───────┐
    │               │                                 │               │
 [ Копия ]     [ По ссылке ]                     [ Инициализация ] [ Изменение ]
    │               │                                 │               │
(без мод.)        in                                 out             ref
               (read-only)
```
> **Важно:** `ref readonly` **не является** модификатором параметра метода. Он используется *только* для возврата значений из метода и объявления локальных переменных.

### Детальное поведение для структур (`struct`):

**1. Без модификатора (`Method(MyStruct data)`)**
* **Передача**: Полное копирование всех байт структуры на стек метода.
* **Изменения внутри**: Видны только внутри метода. Вызывающий код изменения не увидит.
* *Исключение для `Span<T>`*: Так как `Span` сам является ссылкой, изменения ячеек памяти внутри него видны снаружи, а изменения границ самого `Span` — нет.

**2. Модификатор `in` (`Method(in MyStruct data)`)**
* **Передача**: По ссылке (указатель). Исключает копирование больших структур.
* **Контракт**: Только для чтения. Попытка изменить поля внутри метода вызовет ошибку компиляции.
* ⚠️ **Внимание**: Если структура **не** помечена как `readonly struct`, компилятор создаст её скрытую защитную копию в памяти при вызове её методов или свойств, чтобы гарантировать неизменяемость оригинала.
* 💡 **Решение**: Всегда помечайте структуры, передаваемые через `in`, как `readonly struct`.

**3. Модификатор `out` (`Method(out MyStruct data)`)**
* **Передача**: По ссылке.
* **Контракт**: Выходной параметр. Метод обязан присвоить новое значение переменной до своего завершения. Старое значение внутри метода прочитать нельзя.

**4. Модификатор `ref` (`Method(ref MyStruct data)`)**
* **Передача**: По ссылке.
* **Контракт**: Чтение и запись. Переменная должна быть инициализирована до вызова метода. Все изменения структуры сразу видны вызывающему коду.

## 4. Специфика возврата значений: `ref readonly`

Поскольку модификатор `in` нельзя использовать для возвращаемого значения метода, для этих целей существует универсальный синтаксис `ref readonly`.

**Когда использовать:**
Когда у вас есть крупное поле-структура внутри класса, и вы хотите предоставить к нему быстрый доступ снаружи без копирования байт (производительность) и без возможности его модификации (инкапсуляция).

```csharp
public class DataContainer
{
    private LargeStruct _veryLargeData; // Лежит в куче внутри экземпляра класса

    // Возвращаем прямую readonly-ссылку на внутреннюю память класса
    public ref readonly LargeStruct GetData() => ref _veryLargeData;
}

// Использование:
ref readonly var dataRef = ref container.GetData(); // 0 байт скопировано
// dataRef.Value = 10; // Ошибка компиляции: только для чтения!
```

## 5. Quick-Check при написании кода (Архитектурные паттерны)

* **Нужно распарсить строку/массив байт без выделения памяти?**
  👉 Используйте `ReadOnlySpan<char>` / `ReadOnlySpan<byte>`.

* **Нужно передать структуру размером более 16–24 байт в метод?**
  👉 Добавьте модификатор `in`, а саму структуру объявите как `readonly struct`.

* **Нужно посчитать что-то через LINQ на типе `Span<T>`?**
  👉 **Стоп.** Стандартные методы расширения LINQ требуют `IEnumerable<T>`. Попытка передать туда `Span<T>` приведет к ошибке компиляции или к боксингу (полной потере смысла `ref struct`). Используйте стандартный цикл `for`/`foreach` (он быстрее) или специализированные методы из `System.MemoryExtensions`.

* **Нужно выделить массив динамически, но строго на стеке?**
  👉 Используйте `stackalloc T[size]`. Но помните: если `size` не контролируется и может быть большим, вы поймаете `StackOverflowException`. Если есть риск переполнения стека — используйте `ArrayPool<T>.Shared.Rent()`.
